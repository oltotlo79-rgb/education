## この巻のまとめ

この巻の UNIT 01〜10 で、次のことができるようになったかを確かめましょう。できたものに印を付けてください。

**UNIT 01: ユニットテスト・境界値・表の形のテスト**

- ☐ テストの段（ユニット・DB の結合・HTTP・E2E）の違いと、細かい決まりを下の段で確かめる理由を説明できる
- ☐ 「1〜80 文字」のような決まりから、境界値（0・1・80・81）と、間違えやすい入力（空白・全角の空白・日本語・絵文字）を選べる
- ☐ 名前付きの行を表に並べ、1つの確かめ方を全部の行に当てて、合わない行をまとめて報告するテストを書ける
- ☐ わざと間違えた版に同じ表を当てて、テストが失敗することを確かめられる。短い日本語だけの表では `len()` の間違いを見つけられない理由を言える
- ☐ 文字（`chars().count()`）・バイト（`len()`）・UTF-16 の単位の3つの数え方の違いを、絵文字と「が」で説明できる
- ☐ `assert_eq!` の失敗の表示（`left` と `right`）を読み、表と関数のどちらが間違っているかを考えられる
- ☐ `#[test]` を async fn に付けたエラーと、結果を確かめないテストが何も守っていないことを説明できる

**UNIT 02: リポジトリの結合テスト**

- ☐ リポジトリを、偽物ではなく本物の DB（一時フォルダの libSQL ファイル）で確かめる理由を、`LIKE` の `ESCAPE` の例で説明できる
- ☐ 準備・操作・確かめの形で、成功・見つからない・他人・版の食い違いを、1つずつ確かめるテストを書ける
- ☐ SQL から `ESCAPE` を消すと、ユニットテストは通ったまま、結合テストだけが失敗することを確かめられる
- ☐ 削除の SQL から持ち主の条件を消したときの失敗を読み、`assert!` に実際の値を出す文を足せる
- ☐ 1つの DB ファイルを使い回したテストが、実行のたびに違う理由（UNIQUE・locked・表がもうある）で失敗することと、`common::test_db()` で直す理由を言える
- ☐ 検索の大文字と小文字・セッションの期限ちょうど・ユーザーを消したときの CASCADE を、本物の DB で確かめられる

**UNIT 03: HTTP のテスト**

- ☐ レスポンスの4つの部分（状態コード・ヘッダー・Set-Cookie・本文）を全部表示して読み、それぞれ何を確かめればよいかを言える
- ☐ assert_redirect や cookie_attributes のような確かめの道具を作り、#[track_caller] で、失敗の場所をテストの行にできる
- ☐ 本文を contains ではなく、scraper の CSS セレクターで要素を決めて確かめる理由を、空の一覧でも通ってしまう例で説明できる
- ☐ 同じ名前のヘッダーを get_all で全部読み、名前で探す理由（Set-Cookie の順番は決まっていない）を言える
- ☐ body_text のあとでレスポンスを使えない E0382 を読み、状態コードを先に取っておく形に直せる

**UNIT 04: property test・fuzz・入力の読み取り**

- ☐ 「どんな入力でも成り立つ決まり」を関数で書き、proptest にでたらめな入力を作らせて確かめられる
- ☐ 失敗した入力が縮められる（shrink）様子と、種が .proptest-regressions に保存される仕組みを説明できる
- ☐ でたらめな入力を HTTP の入口に送り、500 にならないことを確かめ、見つかった入力（NUL で始まる題）の原因を追える
- ☐ cargo-fuzz（WSL の nightly）で fuzz target を書いて動かし、見つかった入力を cargo fuzz fmt で読める
- ☐ でたらめな試しは見つけない回もあることと、作り方を間違いの出やすい形に寄せる理由を言える

**UNIT 05: E2E・ブラウザ・アクセシビリティ**

- ☐ Playwright で本物の Chrome を動かし、いちばん大事な流れ（登録 → 作成 → 一覧 → ログアウト）を1本のテストで確かめられる
- ☐ webServer で、テストのたびに RustNote を新しい DB で起動する設定を書ける
- ☐ getByLabel・getByRole で、画面に書かれた名前で探す理由を、アクセシビリティと結び付けて言える
- ☐ maxlength が UTF-16 で数えることを本物のブラウザで確かめ、守りはサーバーの parse がする理由を言える
- ☐ axe の指摘（landmark-unique）を読み、aria-label で直せる

**UNIT 06: 守りの回帰テスト**

- ☐ 攻撃の種類ごとにテスト関数を分け、入口を表に並べて、全部の入口で止まることと、何も変わっていないことを確かめられる
- ☐ assert に攻撃と入口の名前を書き、失敗をすぐ読めるようにできる
- ☐ 守りを1つずつ外した版で、どのテストが止まるかの表を作り、テストのデータの抜け（本文が空）を見つけられる
- ☐ cargo-mutants の caught・missed・unviable を読み、SQL の文字列の中は壊さないことを言える
- ☐ まだ無い守りのテストを #[ignore = "理由"] で置き、--ignored・--include-ignored で動かせる

**UNIT 07: tracing・メトリクス・health・SLO**

- ☐ アクセスログを tracing の構造化ログ（項目つきの JSON の1行）にして、項目で絞り込める理由を言える
- ☐ subscriber を入れないとログが出ないこと、init を2回呼ぶと panic すること、RUST_LOG で量を変えられることを説明できる
- ☐ 状態コードの種類ごとの数と応答時間のヒストグラムを数え、/metrics で Prometheus の形で返せる
- ☐ /health が知らせること（DB まで届くか）と、知らせないこと（遅い・5xx が多い）を言える
- ☐ SLO とエラーの予算を決め、/metrics の数から、守れたかと予算の使い方を計算できる

**UNIT 08: benchmark・profile・メモリの使い方**

- ☐ criterion で関数の速さを測り、time の3つの数と外れ値を読める（harness = false・black_box の理由も言える）
- ☐ 遅いと感じたら部分ごとに測り、ログインの大部分が Argon2 の照合であることを、数で示せる
- ☐ debug と release で速さが何倍も違うことを確かめ、速さは release で測る理由を言える
- ☐ 数える global allocator で、借りた回数とピークを測れる
- ☐ Argon2 が1回 19 MiB 使うことから、同時のログインの数とメモリの関係を計算できる

**UNIT 09: 負荷試験・背圧・容量**

- ☐ oha で release の RustNote に負荷をかけ、1秒あたりの回数・パーセンタイル・状態コードの内訳を読める
- ☐ ログインの同時の数を変えて測り、CPU の数を超えると回数が減り、メモリだけが増えることを示せる
- ☐ Semaphore の整理券で、Argon2 を同時に計算する数とメモリの上限を決める背圧を入れられる
- ☐ 全部 403 でも Success rate 100% と出ること、サーバーが無くても oha は exit=0 で終わることを知っている
- ☐ 待たせる背圧と断る背圧の違いと、容量がメモリと待ち時間の先に限界が来るほうで決まることを言える

**UNIT 10: CI・依存・供給網・事故の対応**

- ☐ CI の fmt --check・clippy -D warnings・test --locked を手元で動かし、1つでも失敗したら止まる理由を言える
- ☐ Cargo.lock と --locked で、毎回同じ版の部品を使う理由を、失敗の例で説明できる
- ☐ cargo audit で部品の弱点を調べ、cargo tree -i でどこから来ているかをたどれる
- ☐ 直せない弱点に、使わない機能を外す・audit.toml に理由と見直す日を書いて受け入れる、と手を打てる
- ☐ 部品の弱点が見つかった日の事故の対応の順番を言え、cargo audit を毎日動かす理由を言える

## 用語ミニ辞典

この巻（UNIT 01〜10）に出てきた用語です。

### UNIT 01 の用語

| 用語 | 意味 |
|---|---|
| ユニットテスト | 関数や型のような小さな部品1つを、ほかから切り離して確かめるテスト |
| テストの段 | ユニット・DB の結合・HTTP・E2E のように、確かめる範囲の広さで分けたテストの種類 |
| 境界値 | 決まりが切り替わる境目の値。端と、その1つ外側を試す |
| 表の形のテスト（table-driven test） | 入力と期待する結果の組を表に並べ、同じ確かめ方で1行ずつ試すテスト |
| `#[cfg(test)]` | `cargo test` のときだけコンパイルする印。本番の実行ファイルには入らない |
| `assert_eq!` | 2つの値が等しいことを確かめる。違えば `left` と `right` を表示して panic する |
| わざと間違えた版 | テストが間違いを見つけられるかを確かめるために、わざと壊した関数 |
| ミューテーションテスト | わざと間違いを入れて、テストが気づくかを道具で自動に確かめる方法 |
| ゼロ幅接合子（U+200D） | 絵文字どうしをつないで1つに見せる、見えない文字 |
| UTF-16 の単位 | 文字を 16 ビットずつで表したときの数。ブラウザの `maxlength` はこれで数える |
| `#[tokio::test]` | async のテストに付ける印。Tokio のランタイムを用意してから動かす |

### UNIT 02 の用語

| 用語 | 意味 |
|---|---|
| 結合テスト | いくつかの部品を、本物どうしでつないで確かめるテスト。ここでは、リポジトリと本物の DB |
| Arrange・Act・Assert | テストを、準備する・操作する・確かめるの3つに分けて書く形 |
| 偽物（fake） | テストのために作った、本物の代わりの実装。SQL は動かないので、SQL の間違いには気づけない |
| `common::test_db()` | テストごとに一時フォルダを作り、マイグレーション済みの空の DB を渡す RustNote の関数 |
| `TempDir` | `tempfile` クレートの一時フォルダ。片付けられる（drop される）と、フォルダごと消える |
| `ESCAPE '\'` | `LIKE` の中で、`\` のうしろの文字（`%`・`_`）を、ただの文字として扱わせる指定 |
| `VersionMismatch` | 更新しようとした version が、今の version と違ったときのエラー（楽観的ロック） |
| 共有しているもの | DB のファイル・ポート番号・環境変数・今の時刻など、テストどうしで同じものを使う所。ときどき失敗するテストの原因になる |
| `database is locked` | ほかの接続が書いている最中で、DB を使えなかったときの SQLite のエラー |
| `ON DELETE CASCADE` | 参照先の行が消えたら、参照している行も一緒に消す、という表の約束 |

### UNIT 03 の用語

| 用語 | 意味 |
|---|---|
| ヘッダー | レスポンスの本文の前に付く「名前: 値」の行。同じ名前の行が、いくつあってもよい |
| `Set-Cookie` | クッキーを渡すヘッダー。`HttpOnly`・`Secure`・`SameSite`・`Path`・`Max-Age` などの属性が付く |
| CSS セレクター | `ul.note-list li a` のように、HTML の要素を場所で指定する書き方 |
| `scraper` | HTML を読み、CSS セレクターで要素を探すクレート |
| `#[track_caller]` | 関数の中で失敗したとき、その関数を呼んだ行を、失敗の場所として表示させる印 |
| `get_all` | 同じ名前のヘッダーを、全部取り出すメソッド（`get` は1つ目だけ） |
| 守りのヘッダー | `X-Frame-Options`・`Content-Security-Policy` など、ブラウザに守り方を伝えるヘッダー |

### UNIT 04 の用語

| 用語 | 意味 |
|---|---|
| property test | どんな入力でも成り立つ決まりを、道具が作るたくさんの入力で確かめるテスト |
| proptest | Rust の property test のクレート。`proptest!` と strategy で入力を作る |
| strategy | 入力の作り方。正規表現の文字列・`any::<u32>()`・`prop_oneof!` など |

| cargo-fuzz | libFuzzer を使う Rust の fuzz の道具。nightly で動く |
| NUL | 番号が 0 の文字。SQLite の `length()` は NUL より前だけを数える |
