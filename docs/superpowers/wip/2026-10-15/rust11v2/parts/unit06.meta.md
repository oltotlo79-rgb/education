title: 守りの回帰テスト
---checklist
- ☐ 攻撃の種類ごとにテスト関数を分け、入口を表に並べて、全部の入口で止まることと、何も変わっていないことを確かめられる
- ☐ assert に攻撃と入口の名前を書き、失敗をすぐ読めるようにできる
- ☐ 守りを1つずつ外した版で、どのテストが止まるかの表を作り、テストのデータの抜け（本文が空）を見つけられる
- ☐ cargo-mutants の caught・missed・unviable を読み、SQL の文字列の中は壊さないことを言える
- ☐ まだ無い守りのテストを #[ignore = "理由"] で置き、--ignored・--include-ignored で動かせる
---glossary
| 回帰テスト | 一度できた守りや直した間違いが、あとの変更で元に戻っていないかを、毎回確かめるテスト |
| IDOR | 他人のデータの ID を指定して、見たり変えたりする攻撃 |
| ミューテーションテスト | プログラムをわざと少しずつ壊した版を作り、テストが気づくかを調べること |
| cargo-mutants | Rust の関数や記号を機械的に書き換えて、ミューテーションテストをする道具 |
| caught・missed・unviable | 倒した・見逃した・組み立てられなかった、の3つの結果 |
| `#[ignore]` | ふだんは動かさないテストの印。`--ignored` で動かす |
| 405 Method Not Allowed | その URL は、その方法（GET など）では受け付けない、という返事 |
