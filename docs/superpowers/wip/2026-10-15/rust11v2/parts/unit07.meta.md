title: tracing・メトリクス・health・SLO
---checklist
- ☐ アクセスログを tracing の構造化ログ（項目つきの JSON の1行）にして、項目で絞り込める理由を言える
- ☐ subscriber を入れないとログが出ないこと、init を2回呼ぶと panic すること、RUST_LOG で量を変えられることを説明できる
- ☐ 状態コードの種類ごとの数と応答時間のヒストグラムを数え、/metrics で Prometheus の形で返せる
- ☐ /health が知らせること（DB まで届くか）と、知らせないこと（遅い・5xx が多い）を言える
- ☐ SLO とエラーの予算を決め、/metrics の数から、守れたかと予算の使い方を計算できる
---glossary
| 構造化ログ | 文ではなく、名前つきの項目の集まりで書いたログ。項目で絞り込める |
| `tracing` | Rust で、出来事（イベント）と、その項目を記録するクレート |
| subscriber | tracing の記録を受け取り、どこに・どんな形で書くかを決めるもの |
| `RUST_LOG` | tracing-subscriber の EnvFilter が読む、ログの量を決める環境変数 |
| メトリクス | リクエストの数・失敗の数・応答時間の分布など、動いている様子を表す数 |
| ヒストグラム | 「この時間以下だった数」を、区切りごとに数えたもの |
| SLO | 成功の割合・速さなど、利用者から見た良さの目標を、数で決めたもの |
| エラーの予算 | SLO の残り。99.9% なら 0.1% までは失敗してよい |
