title: ルートの一覧と実装の順番
---checklist
- ☐ 全部の URL を「メソッド・URL・誰が・期待する状態コードと移り先」の表にし、本物のルーターで1行ずつ確かめるテストにできる
- ☐ 未ログイン・持ち主・ほかの人の3通りを並べ、断られるべき人が断られることも表に入れる理由を言える
- ☐ 薄い縦切りの順番（`/health` → 登録・ログイン → 一覧・作成 → …）で作る理由を説明できる
- ☐ 新しい URL を、表に行を足す → 赤 → 作る → 緑、の順で足せる
- ☐ `#[route]` がレイアウトのエラー画面を通らず、`AppError::NotFound` が 500 になる理由と、`not_found()` で直す方法を言える
- ☐ 同じ URL・同じメソッドのページを2つ書いたときの panic を読める
---glossary
| ルートの一覧 | URL ごとの約束（メソッド・誰が・期待する返事）をまとめた表 |
| 薄い縦切り | 1つの機能を、画面から DB まで、すべての層を通して小さく作ること |
| 赤と緑 | テストが失敗している状態（赤）と、通っている状態（緑） |
| `Router::handle` | サーバーを起動せずに、ルーターに要求を1つ処理させるメソッド |
| `..row(…)` | 構造体を作るとき、残りの項目をほかの値から写す書き方 |
| `not_found()` | Topcoat の 404 のエラーを作る関数。`#[route]` の中で 404 を返すときに使う |
| `text/plain` | 本文が、HTML ではない、ただの文字であることを表す種類 |
