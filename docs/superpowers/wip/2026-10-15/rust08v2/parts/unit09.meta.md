title: OIDC・外の認証サービス・MFA・回復
---checklist
- ☐ OIDC の Authorization Code フローと PKCE の流れを説明でき、code_challenge を作って RFC 7636 の例と一致することを確かめられる
- ☐ state と nonce の役目と、state を確かめないとログインの CSRF が起きる理由を言える
- ☐ TOTP を自分で計算して RFC 6238 の例と一致することを確かめ、時計のずれと同じ数字の使い回しの扱いを説明できる
- ☐ パスワードの再設定のトークンを、ハッシュで保存・1 時間・1 回だけで作れる
- ☐ 外の認証サービスの利用者を、メールではなく iss と sub で結び付ける理由を言える
---glossary
| OIDC（OpenID Connect） | 外の認証サービスで本人を確かめ、結果を ID トークンで受け取る決まり |
| Authorization Code フロー | 認証サービスから code を受け取り、サーバーどうしで ID トークンと交換する流れ |
| PKCE | code_verifier のハッシュ（code_challenge）を先に渡し、交換のときに code_verifier を見せる仕組み |
| `state` | コールバックが、自分の始めたログインの続きかを確かめる値 |
| `nonce` | ID トークンの使い回しを断るために、ID トークンに入れてもらう値 |
| ID トークン | 認証サービスが署名した「この人は誰か」の証明。iss・aud・exp・sub などを持つ |
| MFA（多要素認証） | 知っている物と持っている物など、2つ以上で本人を確かめること |
| TOTP | 秘密の鍵と時刻から、30 秒ごとに変わる数字を作る仕組み（RFC 6238） |
| `sub` | 認証サービスの中で変わらない、利用者の番号 |
