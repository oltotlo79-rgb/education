## この巻のまとめ

この巻の UNIT 01〜10 と総合演習で、次のことができるようになったかを確かめましょう。できたものに印を付けてください。

**UNIT 01: 版を固定する設定ファイル**

- ☐ `Cargo.toml`・`Cargo.lock`・`rust-toolchain.toml`・`rustfmt.toml`・`.gitignore`・`.env.example` の6つについて、読む道具と、決めていることを言える
- ☐ `"=1.53.3"`（その版だけ）と `"1.53.3"`（1.53.3 以上 2.0.0 未満）の違いを、`cargo update -p tokio --dry-run` の結果で説明できる
- ☐ `rust-version`（最低の版）と `rust-toolchain.toml`（このフォルダで使う版）の違いと、`overridden by` の意味を説明できる
- ☐ `--locked` が `Cargo.lock` の書き換えを止めることと、`Dockerfile` と `ci.yml` が `--locked` を付けている理由を説明できる
- ☐ features は依存のつながり全体で足し算されることを、`cargo tree -f "{p} [{f}]"` の出力で確かめられる。自分が使う機能は、自分の `Cargo.toml` に書く
- ☐ `cargo tree -i クレート名` で、あるクレートを誰が使っているかをたどれる（`ring` ← rustls ← hyper-rustls ← libsql）
- ☐ 版が古い（`requires rustc 1.99`）・機能の名前の打ち間違い・`--locked` の食い違い・checksum の食い違い・`#[tokio::main]` の E0433 を読み、直すファイルを決められる
- ☐ `git check-ignore -v` で、ファイルが `.gitignore` のどの決まりで外されるかを確かめられる

**UNIT 02: 表を作る SQL と DB の入口**

- ☐ `migrations/` の3つの SQL ファイルが作る表・索引・制約と、記録簿の `schema_migrations` を言える
- ☐ `db::migrate` が、未適用の版だけを古い順に、1つずつトランザクションの中で適用し、SQL の実行と記録を同じトランザクションに入れる理由を説明できる
- ☐ `migrate` を2回かけても2回目は何もしない（冪等である）ことを確かめられる
- ☐ WAL（ファイルに記録される）と、`busy_timeout`・`foreign_keys`（接続ごと）の違いを、実際の値で説明できる
- ☐ マイグレーションが途中で失敗したとき、作りかけの表と索引が `rollback` で残らないことと、直したあとに失敗した版だけが流れることを確かめられる
- ☐ 適用済みの SQL ファイルを書き換えてはいけない理由を、古い DB と新しい DB の食い違いで説明し、変更を新しい版として足せる
- ☐ `EXPLAIN QUERY PLAN` で、一覧の SQL が索引を使っているかを確かめられる

**UNIT 03: 設定と起動の順番**

- ☐ src/config.rs が環境変数から Config を作る決まり（既定値・Turso ならトークン・空のトークン）を、実際の結果で説明できる
- ☐ Secret 型が {:?} でトークンを隠し、{} では表示させない仕組みと、expose() の役目を言える
- ☐ src/main.rs の起動の順番を言え、どの段で止まると DB のファイルが残るかを、本物の実行ファイルで確かめられる
- ☐ .env は、すでにある環境変数を上書きしないことを確かめられる
- ☐ src/lib.rs の pub mod を消したときの E0432 と、edition 2024 の set_var の E0133 を読める

**UNIT 04: ドメインの型とエラーの分類**

- ☐ 検査済みの型の中身が private で、parse を通らずには作れない（E0423）ことと、UserId と NoteId を取り違えられない（E0308）ことを説明できる
- ☐ タイトル・本文・メール・パスワード・ID の数え方とそろえ方を、例4-3の結果（NUL・絵文字・全角）で言える
- ☐ NewNote::parse が問題を全部集める理由を、? で書いた版と比べて説明できる
- ☐ RepoError と AppError の2つの層、#[from] と From による ? の変換（無いと E0277）、status_code と public_message の役目を言える
- ☐ NoteQuery の pub な項目で page: 0 を作ると、debug と release でどうなるかを確かめ、直し方を言える

**UNIT 05: リポジトリ**

- ☐ trait と libSQL の実装を組にし、AppState が Arc<dyn … + Send + Sync> で持つ理由と、#[async_trait] が要る理由（無いと E0038）を説明できる
- ☐ notes.rs のどの SQL にも user_id = ? が入っていることを示し、消すと notes_are_isolated_per_owner だけが止めることを確かめられる
- ☐ 楽観的ロックの update が、0 行のときに find で VersionMismatch（409）と NotFound（404）を分ける理由を言える
- ☐ LIKE の % と _ を escape しないと、100 で「1000円」まで当たることを示せる
- ☐ UserRecord（ハッシュ付き）と User の使い分けと、セッションをトークンの SHA-256 で探す仕組みを言える

**UNIT 06: ログイン・お知らせ・共有の状態**

- ☐ Argon2id のハッシュを spawn_blocking で作る理由と、借り物を渡すと E0521 になる理由を説明できる
- ☐ 登録されていないメールでもダミーのハッシュで照合する理由を、時間の比較（36〜41 ミリ秒と 4 ミリ秒）で説明できる
- ☐ ログイン・ログインし直し・ログアウトで、__Host-session クッキーと sessions の表がどう変わるかを、curl の結果で言える
- ☐ フラッシュメッセージが一度だけ出るしくみと、書き換えられたクッキーで何も出ない理由を言える
- ☐ AppState が Arc と Send + Sync で共有される理由を、Rc のエラー（E0277）で説明できる

**UNIT 07: 画面の枠・部品・登録とログインの画面**

- ☐ module_router!() のファイルの並びと URL の対応、build_router で足す4つ（クッキー・セッション・アセット・共有の状態）を言える
- ☐ #[layer] の access_log と #[layout] の root_layout の役目と、405・403 がアクセスログに残らない理由を説明できる
- ☐ view! の文字の書き方（囲まないと expected view node）と、(式) の自動のエスケープを、本物の HTML で示せる
- ☐ #[component] の名前付きの引数（忘れると E0277）と、href! がページの関数だけを行き先にできることを説明できる
- ☐ 登録・ログイン・ログアウト・ヘルスチェックの状態コード（400・409・303・401・405・403・200）を、curl の結果で言える

**UNIT 08: ノートの CRUD**

- ☐ 一覧・作成・詳細・編集・切り替え・削除の URL・メソッド・状態コード（200・303・400・404・409）を、curl の結果で言える
- ☐ module_param! で {id} を NoteId に変え、数字でない・0・無い・他人のノートを、どれも 404 にするしくみを説明できる
- ☐ 2つのタブの編集で 409 になり、もう一度保存すると上書きされる流れと、知らせる内容の足りない所を言える
- ☐ href! に ID を渡し忘れても、コンパイルが通り、ノートがあるときだけ表示でパニックすることを説明できる
- ☐ 最後より大きいページの文と、UTC のままの日時の表示という改善点を、実際の画面で示せる

**UNIT 09: 見た目**

- ☐ style.css の組み立て（色の変数・全体・ヘッダー・本文の枠・ボタンとフォーム・お知らせ・一覧・詳細）を、view! のクラスの名前と結びつけて説明できる
- ☐ 本物の Chrome で、幅ごとの枠の大きさ・横のはみ出し・CSS が効いた結果を測れ、375px と 320px のヘッダーのはみ出しを flex-wrap で直せる
- ☐ 色の組のコントラスト比を計算し、AA（4.5 : 1）にいちばん近い組を言える
- ☐ asset! と topcoat asset bundle の、印付きの URL と 1 年間の immutable なキャッシュのしくみを説明できる
- ☐ CSS のまちがい（ファイルの名前・閉じ括弧・変数の名前）が cargo build で見つからないことと、それぞれの見つけ方を言える

**UNIT 10: テスト・Docker・Fly.io・CI**

- ☐ tests/common/mod.rs の道具（一時フォルダの DB・テスト用のアセット・Router::handle）と、repository.rs・http.rs が確かめていることを説明できる
- ☐ CI と同じ3つの手順（fmt --check・clippy -D warnings・test --locked）を手元で動かし、41 個のテストの結果と、--locked の止め方を読める
- ☐ Dockerfile の2つの段と .dockerignore を説明し、本物の Docker でビルド・起動・/health を確かめられる（キャッシュの効き方も言える）
- ☐ assets のコピー忘れ・ポートの食い違い・HOST=127.0.0.1 が、それぞれどう見えるかを言える
- ☐ fly.toml の internal_port・force_https・/health のチェックと、コンテナの中の DB が作り直しで消えることを説明できる

**総合演習: RustNote の改善点を直す**

- ☐ 改善点を「失敗するテスト（か実験）を書く → 直す → 通る → 1つのコミット」の順で直せる
- ☐ 項目を private にするとき、まず消して、コンパイラが教える場所を直す進め方ができる
- ☐ 待ち受けの場所を DB より先に取る起動の順番・Argon2 の整理券・守りのヘッダー（1つのモジュールに #[layer] は1つ）を、自分の RustNote に取り入れられる
- ☐ 9つを直したあとに、CI と同じ3つの手順（47 個のテスト）が通ることを確かめられる

| 用語 | 意味 |

| `.dockerignore` | docker build のときに、Docker へ送らないファイルの一覧 |
| `CACHED` | docker build の段の結果を、前のビルドから使い回したという印 |
| volume | コンテナの外に置く、データの置き場。コンテナを作り直しても残る |
| `0.0.0.0` | 「どのネットワークの入口からでも受け付ける」という待ち受けのアドレス。コンテナの外から届くために要る |
| `--locked` | `Cargo.lock` のとおりにビルドし、勝手に版を変えない、という cargo の指定 |
