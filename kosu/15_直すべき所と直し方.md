# 15 直すべき所と直し方（改修の一覧）

> この巻は、業務工数システムのプログラム（GitHub の `master`。2026 年 4 月 17 日のコミット `30d45e7`）を 1 ファイルずつ読んで見つけた「直すべき所」を、**全部** 並べた物です。1 つずつ、次の 4 つを書いています。
>
> - **どこ:** ファイルと行番号（`master` の行番号です。手元のファイルを書き換えていると、ずれることがあります）
> - **今どうなっていて、何が困るか**
> - **どう直すか**（直した後のコード）
> - **直ったことの確かめ方**

> 🔰 **初めての方へ:** 全部をいっぺんに直す必要はありません。§2 の一覧で「🔴 すぐ」の物から、1 つずつ直してください。直し方のコードは、そのまま貼れば動くように書いてあります。ただし **貼る前に、必ず作業用のブランチを作ってください**（§3）。`master` に入れた物は、そのまま本番に出ます（[000_引き継ぎ書_最初に読む](./000_引き継ぎ書_最初に読む.md) の §6）。

### この巻で分かること

- 本番のデータが守られていない所（ログインや権限の確かめ漏れ）と、全部の API にまとめて確かめをかける直し方
- 動かない所・壊れやすい所（不具合）と、その直し方
- リポジトリ・デプロイ・部品（ライブラリ）の整理のしかた
- 直した後に足すテストと、直す順番

## 1. この巻の読み方

### 1.1 印の意味

**急ぐ度**

| 印 | 意味 |
|---|---|
| 🔴 すぐ | 本番のデータが守られていない。ほかの作業より先に直す |
| 🟠 早めに | 動かない、または壊れやすい。使う人が困る |
| 🟡 余裕のある時に | 整理・改善。直さなくても、すぐには困らない |

**どうやって分かったか**

| 印 | 意味 |
|---|---|
| ✅ 手元で再現 | `master` を手元の別のフォルダに書き出し、メモリの中だけのデータベースで動かして、本当にそうなることを確かめた（本番には一切触っていない。§9） |
| 📖 コードから | コードを読んで分かった。動かしては確かめていない |

**番号の頭の文字:** S ＝ 安全（Security）、B ＝ 不具合（Bug）、D ＝ 開発・運用の整理（Development）、T ＝ テスト（Test）。

### 1.2 この巻で使う言葉

| 言葉 | 意味 |
|---|---|
| API（エーピーアイ） | 画面（React）がサーバー（Django）に「データをちょうだい」「これを保存して」と頼む窓口。`/api/member_new/` のような URL の 1 つ 1 つ（07 巻） |
| ログインの確かめ（認証） | 「今、だれがログインしているか」を確かめること。このアプリでは、ログインすると **セッション**（サーバーが覚えておく、その人用のメモ）に従業員番号（`login_No`）が入る |
| 権限の確かめ（認可） | 「その人に、その操作をしてよいか」を確かめること。このアプリでは、人員の表の「権限（`authority`）」と「管理者（`administrator`）」の 2 つのスイッチ（000 巻 §2） |
| CSRF（シーサーフ） | ログインしたままの人が、別の（悪い）サイトを開いた時に、そのサイトが裏でこのアプリへ「消して」などを送らせる攻撃。防ぐには、このアプリの画面だけが知っている合言葉（**CSRF トークン**）を、書き込みの時に一緒に送らせて確かめる |
| CORS（コルス） | 別のサイトの JavaScript が、このアプリの API の返事を読んでよいかを、サーバーが答える仕組み |
| Cookie（クッキー） | ブラウザがサイトごとに覚えておく小さなデータ。ログインのセッションの番号も、CSRF トークンもここに入る |
| ステータスコード | API の返事に付く 3 けたの番号。200 ＝ 成功、400 ＝ 送った物がおかしい、401 ＝ ログインしていない、403 ＝ してはいけない、404 ＝ 見つからない、500 ＝ サーバーの中でエラー（09 巻） |

## 3. 直す前の準備

### 3.1 作業用のブランチを作る

`master` に push すると、GitHub Actions が数分で本番に出します（000 巻 §6、09 巻 §14）。直している途中の物が本番に出ないように、**必ず作業用のブランチで直します**。

```powershell
cd hozen-kosu-React
git switch master
git pull
git switch -c fix/security-step1
```

直し終わったら、ブランチを GitHub に push し、GitHub の画面で **Pull Request**（「このブランチを master に入れてください」というお願い）を作ります。前任者か、もう 1 人に見てもらってから master に入れる（Merge）と、その時に本番に出ます（02 巻）。

### 3.2 本番のデータを、先にバックアップする

直した物を本番に出す前に、本番のデータを残しておきます。

- **Azure のバックアップ:** 本番のデータベース（Azure Database for PostgreSQL）には、Azure が自動で取るバックアップがあります。何日分残っているか、戻す手順を、前任者に確かめておきます（000 巻 §10）。
- **データ管理画面のバックアップ:** 000 巻 §8.2 の 9 種類。ただし、ダウンロードが本番で動いていない恐れがあります（[B-2](#52-b-2-バックアップのダウンロードの-url-に--ができる)）。ダウンロードしたファイルが Excel で開けるかを、必ず確かめてください。

### 3.3 今のテストが全部通ることを確かめる

直す前に、今のテストが通ることを確かめます（12 巻）。

```powershell
python manage.py test --settings=hozen_another.test_settings
```

2026 年 11 月 9 日に `master` の写しで流した時は、**331 個すべて OK** でした（最後に `Ran 331 tests` と `OK` が出ます）。途中に `database table is locked` という長いエラーの文字が出ますが、テストの結果には関係しません（バックアップのテストが裏で動かすスレッドが、テスト用のデータベースを触ろうとして出る物です）。

画面側のテスト（`frontend/src/tests/` の 65 ファイル）も流しておきます。こちらは今回、流していません。

```powershell
cd frontend
npm run test:run
```

### 3.4 1 つ直したら、すぐ確かめて、コミットする

- 1 つの番号（例: [S-4](#44-s-4-ダウンロードの-api-が渡された場所のファイルを確かめずに返して後で消す)）を直したら、テストを流し、手元でその画面を動かしてから、コミットします。
- コミットのメッセージに番号を書いておくと、後で探せます（例: `S-4: ダウンロードを media の中のファイルだけにする`）。
- いくつもの番号を 1 つのコミットに混ぜないでください。何かが壊れた時に、どれのせいか分からなくなります。

## 4. 安全の問題（S）

### 4.0 何が起きているか

このアプリの API は、Django REST framework の `APIView`（07 巻）で書かれています。`APIView` は、何も書かなければ **だれからの頼みでも受け付けます**。そこで、今は API ごとに、最初の数行で「ログインしているか」「権限があるか」を自分で確かめています。

```python
# 今の書き方（例: kosu/views/member_views.py 15〜34 行目の MemberList。短くまとめ、説明のコメントを足した物）
login_no = request.session.get('login_No')       # セッションから、ログイン中の人の従業員番号を出す
if not login_no:                                  # 無ければ「ログインしていない」
  return Response({'status': 'error', 'message': 'ログイン情報が確認できません。'}, status=status.HTTP_401_UNAUTHORIZED)
member_data = member.objects.get(employee_no=login_no)
if not member_data.authority:                     # 「権限」が無ければ断る
  return Response({'status': 'error', 'message': 'アクセス権限がありません。'}, status=status.HTTP_403_FORBIDDEN)
```

この書き方だと、**書き忘れた API は、だれでも使えます**。実際に、画面を表示するための `get` には書いてあるのに、保存・削除の `post`・`put`・`delete` に書き忘れている API がたくさんあります（[S-2](#42-s-2-ログインや権限を確かめていない-api全部)）。画面はボタンを出さないので気付きにくいのですが、API は画面を通さなくても呼べます。

さらに、Django REST framework は、このアプリのような「セッションに番号を入れるだけ」のログインの時には、CSRF の確かめをしません（[S-5](#45-s-5-どのサイトからでもログイン中の人として操作できるcorscookiecsrf)）。

### 4.1 S-1 共通の確かめを作り、全部の API に最初からかける

🔴 すぐ ／ ✅ 手元で再現（この節のコードを `master` の写しに入れ、§9 の確かめが全部通ることを確かめた）

**どこ:** 新しく作る `kosu/permissions.py`、`hozen_another/settings.py` の 61〜70 行目（`REST_FRAMEWORK`）、`kosu/models.py` の 64〜65 行目（`member` の終わり）

**直し方:**

① `kosu/permissions.py` を新しく作ります。

```python
"""ログイン中の人と、その人の権限を確かめる部品（全部の API で共通に使う）。

settings.py の REST_FRAMEWORK で「最初から全部の API にかける」設定にするので、
ログインが要らない API（ログイン・ログアウト・ヘルプ）だけ AllowAny を付けて外す。
"""
from rest_framework import exceptions
from rest_framework.authentication import BaseAuthentication, CSRFCheck
from rest_framework.permissions import BasePermission

from .models import member


class LoginNoAuthentication(BaseAuthentication):
  """セッションの login_No から、ログイン中の人（member）を探す。"""

  def authenticate(self, request):
    login_no = request._request.session.get('login_No')
    if not login_no:
      return None                      # ログインしていない → request.user は None
    login_member = member.objects.filter(employee_no=login_no).first()
    if login_member is None:
      return None                      # 人員から消された人 → ログインしていない扱い
    self.enforce_csrf(request)         # ログイン中の人の書き込みは、CSRF トークンも確かめる
    return (login_member, None)

  def enforce_csrf(self, request):
    # DRF の SessionAuthentication.enforce_csrf と同じ確かめ方
    def dummy_get_response(request):
      return None
    check = CSRFCheck(dummy_get_response)
    check.process_request(request)
    reason = check.process_view(request, None, (), {})
    if reason:
      raise exceptions.PermissionDenied(f'CSRF Failed: {reason}')

  def authenticate_header(self, request):
    # これを返すと、ログインしていない時に 403 ではなく 401 になる（画面はログイン画面へ戻る）
    return 'Session'


class IsLoggedIn(BasePermission):
  """ログインしていること。"""
  def has_permission(self, request, view):
    return isinstance(request.user, member)


class HasAuthority(IsLoggedIn):
  """ログインしていて、「権限」が付いていること（人員・班員の画面）。"""
  def has_permission(self, request, view):
    return super().has_permission(request, view) and bool(request.user.authority)


class IsAdministrator(IsLoggedIn):
  """ログインしていて、「管理者権限」が付いていること（管理者・定義の編集の画面）。"""
  def has_permission(self, request, view):
    return super().has_permission(request, view) and bool(request.user.administrator)
```

<!-- first-use -->

> **▶ ここで初めて出てくるコード**
>
> - **`.process_request()`**（Django）: Django のミドルウェア（頼みの前後に動く部品）の、頼みが来た時に動くメソッド。`CSRFCheck` では、クッキーから CSRF の合言葉を読み出します。
> - **`.process_view()`**（Django）: Django のミドルウェアの、画面（ビュー）を動かす直前に動くメソッド。`CSRFCheck` では、送られてきた合言葉が合っているかを確かめ、合わなければ理由の文を返します。
> - **`.PermissionDenied()`**（Django REST framework）: `exceptions.PermissionDenied('…')` は、「してはいけない」というエラーを起こす物。Django REST framework が受け止めて、403 の返事にします。
> - **`bool()`**（Python）: 値を `True`・`False` にする関数。空の文字列や `None` は `False`、中身があれば `True` です。
> - **`BaseAuthentication`**（Django REST framework）: 「この頼みは、だれからか」を調べる部品の土台。これを受け継いで `authenticate` を書き、だれか分かったら `(その人, None)`、分からなければ `None` を返します。
> - **`CSRFCheck`**（Django REST framework）: Django の CSRF の確かめ（`CsrfViewMiddleware`）を、Django REST framework の中から使うための部品。`rest_framework.authentication` から読み込みます。
> - **`BasePermission`**（Django REST framework）: 「この人に、この API を使わせてよいか」を決める部品の土台。これを受け継いで `has_permission` を書き、よければ `True` を返します。`False` なら 401 か 403 になります。
> - **`.user`**（Django）: Django の `request.user` は、今ログインしている人（していなければ「だれでもない人」）です。`request.user.is_authenticated` で、ログインしているかが分かります。

### 4.4 S-4 ダウンロードの API が、渡された場所のファイルを確かめずに返して、後で消す

**どこ:** `kosu/views/asynchronous_views.py` 242〜263 行目（`download_file`）、219〜238 行目（`check_task_status`）、`frontend/src/AdministratorPage/AdministratorLoading.tsx` 39〜46 行目、`kosu/tests/test_backend.py` 2455〜2462 行目


**何が困るか:**

- ログインの確かめが無く、しかも **ファイルの場所を確かめていません**。バックアップとは関係の無い、サーバーの中のファイルまで渡してしまいます（✅ 手元で、`media` の外のファイルの中身が返りました）。
- 渡した後に、そのファイルを消す処理が付いています。消えてはいけないファイルまで消える恐れがあります（📖 手元の Windows では、ファイルが開いたままなので消えませんでした。本番の Linux では、開いたままでも消せます）。
- `response.close` を丸ごと差し替えているので、本来の `close`（開いたファイルを閉じる処理）が動かず、ファイルが開いたまま残ります。
- 今のテスト `test_download_file`（`test_backend.py` 2455 行目）は、`media` の外の一時ファイルをダウンロードできることを「正しい」として確かめています。

**直し方:**

① サーバー（`asynchronous_views.py`）: ファイルの **名前だけ** を受け取り、置き場所（`settings.MEDIA_ROOT`）とつなげて、その中にあることを確かめます。

```python
import os
from pathlib import Path
from django.conf import settings
from django.http import JsonResponse, FileResponse
from rest_framework import status
from rest_framework.decorators import api_view, permission_classes
from ..permissions import IsAdministrator


@api_view(['GET'])
@permission_classes([IsAdministrator])
def download_file(request):
  backup_dir = Path(settings.MEDIA_ROOT).resolve()               # バックアップの置き場所
  file_name = os.path.basename(request.GET.get('file_name', ''))  # 名前だけにする（../ や C:/… を捨てる）
  file_path = (backup_dir / file_name).resolve()
  if not file_name or file_path.parent != backup_dir or not file_path.is_file():
    return JsonResponse({'status': 'error', 'message': 'ファイルが見つかりません。'}, status=status.HTTP_404_NOT_FOUND)

  response = FileResponse(open(file_path, 'rb'), as_attachment=True, filename=file_name)
  original_close = response.close
  def close_then_delete():          # 送り終わったら、先にファイルを閉じてから消す
    original_close()
    try:
      file_path.unlink()
    except OSError:
      pass
  response.close = close_then_delete
  return response
```

<!-- first-use -->

> **▶ ここで初めて出てくるコード**
>
> - **`.is_file()`**（Python）: `Path` の `.is_file()` は、その場所にファイルがあれば `True` を返すメソッド。フォルダや、何も無い時は `False` です。
> - **`.unlink()`**（Python）: `Path` の `.unlink()` は、そのファイルを消すメソッド。消せない時は `OSError` になります。
> - **`original_close()`**（Python）: この巻のダウンロードの直し方で、`FileResponse` が元から持っていた `close`（開いたファイルを閉じる処理）を、変数 `original_close` に取っておいた物。先にこれを呼んでファイルを閉じてから、ファイルを消します。
> - **`OSError`**（Python）: ファイルを開く・消すなど、OS とのやり取りで起きるエラーのまとめ役。`except OSError:` で、ファイルが無い・使用中で消せない、などをまとめて受け止めます。

**直し方:**

① `settings.py` の 53〜59 行目と 76〜77 行目を、次のようにします。

> **▶ ここで初めて出てくるコード**
>

> - **`@method_decorator`**（Django）: `@method_decorator(ensure_csrf_cookie, name="dispatch")` をクラスの上に付けて、そのクラスの画面に印を付けます。

```python
    settingReset = post_data.get('settingReset')
```

> 💡 `hmac.compare_digest` は、`==` と同じく「同じか」を比べますが、どこまで合っていたかで答えの速さが変わりません。文字列のまま渡すと、日本語の入ったパスワードでエラーになるので、`.encode('utf-8')` でバイトにしてから比べます。


### 5.8 B-8 データのロードが途中で失敗すると、データが半分だけ消える

🟠 早めに ／ 📖 コードから

**どこ:** `kosu/tasks.py` の `load_choice_file`（735〜743 行目）、`load_setting_file`（990〜1010 行目）、`load_def_file`（630〜648 行目）、`load_kosu_file`（197〜235 行目）

**今:** ロードは「先に消す → 1 行ずつ足す」の順で、**途中で失敗しても、消した物は戻りません**。たとえば作業詳細選択肢のロードは、最初に全部消してから足すので、Excel の途中の行に変な値があると、選択肢が途中までしか無い状態になります。

**直し方:** 「消す → 足す」を `transaction.atomic()` で囲み、全部うまくいった時だけ残るようにします。一時ファイルの片付けは `finally` にまとめます。

```python
from django.db import IntegrityError, transaction


def load_choice_file(file_path):
  try:
    wb = openpyxl.load_workbook(file_path)
    ws = wb.worksheets[0]
    expected_headers = ['定義記号', '作業詳細']
    actual_headers = [ws.cell(1, col).value for col in range(1, len(expected_headers) + 1)]
    if actual_headers != expected_headers:
      return {'status': 'error', 'message': '無効なファイルフォーマットです。'}, None

    with transaction.atomic():            # この中の変更は、全部うまくいった時だけ残る
      def_choice.objects.all().delete()
      for i in range(2, ws.max_row + 1):
        def_choice.objects.create(def_symbol=ws.cell(row=i, column=1).value,
                                  def_select=ws.cell(row=i, column=2).value)
    return {'status': 'success'}, None
  except Exception as e:
    return {'status': 'error', 'message': str(e)}, None
  finally:
    if os.path.exists(file_path):          # うまくいっても、失敗しても、一時ファイルを消す
      os.remove(file_path)
```

<!-- first-use -->

> **▶ ここで初めて出てくるコード**
>
> - **`finally`**（Python）: `try … except` のあと、成功しても失敗しても最後に必ず動く所。

<!-- /first-use -->

1 行ずつ `IntegrityError` を受け止めて飛ばしている物（`load_member_file` など）は、その 1 行を、もう 1 つ内側の `transaction.atomic()` で囲みます。囲まずに受け止めると、外側の取り消しの仕組みが壊れて、次の行から全部失敗します。

```python
    with transaction.atomic():
      for i in range(2, ws.max_row + 1):
        try:
          with transaction.atomic():       # この 1 行だけの区切り。失敗しても、この行だけ取り消す
            member.objects.create(...)
        except IntegrityError as create_e:
          print(f'{i} 行目を飛ばしました: {create_e}')   # 今のコードと同じく print（D-9 で logging に）
```

```python
import json
from rest_framework.test import APIClient
from kosu.models import member, Business_Time_graph
from kosu.tests.test_backend import BaseTestCase


class TestSecurity(BaseTestCase):
    """ログイン・権限・持ち主・CSRF の確かめが効いていることを確かめるテスト"""

    NEW_MEMBER = {'employee_no': 1, 'name': 'x', 'shop': 'P', 'authority': True, 'administrator': True}

    def test_member_new_needs_login(self):
        # ログインしていない → 401、人員はできない
        response = self.client.post('/api/member_new/', self.NEW_MEMBER, format='json')
        self.assertEqual(response.status_code, 401)
        self.assertFalse(member.objects.filter(employee_no=1).exists())

    def test_member_new_needs_authority(self):
        # 「権限」の無い人 → 403
        self.login_as_normal()
        response = self.client.post('/api/member_new/', self.NEW_MEMBER, format='json')
        self.assertEqual(response.status_code, 403)

    def test_cannot_delete_others_kosu(self):
        # 他人の工数は「見つからない」（404）にして、消さない
        others = Business_Time_graph.objects.create(employee_no3=12345, name=self.member, work_day2='2026-01-05')
        self.login_as_normal()
        response = self.client.delete(f'/api/kosu_delete/{others.id}/')
        self.assertEqual(response.status_code, 404)
        self.assertTrue(Business_Time_graph.objects.filter(id=others.id).exists())

    def test_csrf_is_checked_when_logged_in(self):
        # ブラウザと同じく CSRF を確かめるクライアントで、トークン無しの書き込み → 403
        client = APIClient(enforce_csrf_checks=True)

        response = client.post('/api/set_day/', {'day': '2026-01-05'}, format='json')
        self.assertEqual(response.status_code, 403)
        # ログインの返事で配られた csrftoken を付ければ通る
        token = client.cookies['csrftoken'].value
        response = client.post('/api/set_day/', {'day': '2026-01-05'}, format='json', HTTP_X_CSRFTOKEN=token)
        self.assertEqual(response.status_code, 200)
```

## 10. この巻のまとめ

- いちばん大きな問題は、**API ごとに確かめを書いていて、書き忘れが多い** ことです。共通の確かめを 1 つ作って全部の API にかける（[S-1](#41-s-1-共通の確かめを作り全部の-api-に最初からかける)）と、今ある漏れが一度にふさがり、これから API を足す時も安全な側になります。
- **今すぐ** 直すのは、ダウンロード（[S-4](#44-s-4-ダウンロードの-api-が渡された場所のファイルを確かめずに返して後で消す)）、共通の確かめ（[S-1](#41-s-1-共通の確かめを作り全部の-api-に最初からかける)・[S-2](#42-s-2-ログインや権限を確かめていない-api全部)）、CORS・Cookie・CSRF（[S-5](#45-s-5-どのサイトからでもログイン中の人として操作できるcorscookiecsrf)）です。リポジトリの Excel（[S-9](#49-s-9-リポジトリに氏名入りのバックアップの-excel-が記録されている)）は、コードより先に、公開範囲の確認と会社への連絡をします。
- 不具合（B）は、使う人が困っている物（[B-1](#51-b-1-ヘルプ画面の初期化がurl-の--が-1-つ多くて動かない)〜[B-6](#56-b-6-同じ従業員番号の人が-2-人いるとその人の画面がほとんど-500)・[B-10](#510-b-10-ログイン以外の理由でも-401-を返し画面がログイン画面へ飛ぶ)）から直します。
- どれも、**作業用のブランチで直し、テストを流し、手元で確かめてから** master に入れます。master に入れた物は、そのまま本番に出ます。
- 直したら、この巻の該当する行に「済み（日付・コミット）」と書き足しておくと、次の人が助かります。
