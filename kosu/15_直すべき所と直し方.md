## 1. この巻の読み方

### 1.1 印の意味

**急ぐ度**

| 印 | 意味 |
|---|---|
| 🔴 すぐ | 本番のデータが守られていない、または使えなくなる。ほかの作業より先に直す |
| 🟠 早めに | 動かない、または壊れやすい。使う人が困る |
| 🟡 余裕のある時に | 整理・改善。直さなくても、すぐには困らない |

**どうやって分かったか**

| 印 | 意味 |
|---|---|
| ✅ 手元で再現 | `284a16a` を別のフォルダに写し、メモリの中だけのデータベースで動かして、本当にそうなることを確かめた（本番には一切触っていない。§8） |
| 📖 コードから | コードを読んで分かった。動かしては確かめていない |

**番号:** S ＝ 安全（Security）、B ＝ 不具合（Bug）、D ＝ 開発・運用の整理（Development）。番号は前の版と同じ物を使っています（直った物と、直さないと決めた物は、この巻から外したので、番号が飛んでいます）。

### 1.2 「今」と「直した後」の読み方

- **場所:** ファイルと、`284a16a` での行番号。たとえば「`kosu/tasks.py` の 124〜126 行目」。
- **今:** その行の、今のコード（コメントも含めて、ファイルのとおり）。
- **直した後:** 「今」の行を、全部これに置き換えます。
- 「この行の前に入れる」と書いてある物は、何も消さずに、その行の前に足します。

> ⚠️ **行番号は、上から直していくと、ずれます。** 1 つのファイルの中で何か所も直す時は、**下の方の場所から** 直すか、行番号ではなく「今」のコードを、エディターの検索（`Ctrl` ＋ `F`）で探して置き換えてください。

> ⚠️ **本番のホスト名（住所）は、この資料には書いていません。** コードの中で `<本番のホスト名>` と書いた所は、今のファイルに書いてある名前を、そのまま使ってください。

### 1.3 この巻で使う言葉

| 言葉 | 意味 |
|---|---|
| マイグレーション | データベースの表の形の変更を書いたファイル（`kosu/migrations/`）。`migrate` で本物のデータベースに当てる（08 巻） |

| 記録（lock） | `frontend/package-lock.json`。画面の部品を、どの版で入れるかを全部書いた物。`npm ci` は、これのとおりに入れる |

## 4. 安全の問題（S）

### 4.1 S-6 ログインにパスワードが無い（従業員番号だけ）

🔴 すぐ（ただし、やり方は決める必要がある） ／ 📖 コードから

**どこ:** `kosu/views/main_views.py` 175〜221 行目（`Login`）、`hozen_another/settings.py` 160〜162 行目（`SESSION_COOKIE_AGE = 315360000` ＝ 10 年）、`main_views.py` 333〜363 行目（ヘルプの初期化で作る従業員番号 `12345` の管理者）

**今:** 人員の表にある従業員番号を入れれば、その人としてログインできます（000 巻 §2.2）。管理者の番号を知っていれば、管理者として入れます。一度ログインすると、10 年間ログインしたままです。

**何が困るか:** 従業員番号は、名札・書類・メールなどで、ほかの人も知っている物です。共用の PC では、前の人のログインがそのまま残ります。

**直し方（どれにするかは、前任者・会社の IT 担当と決める）:**

| 案 | 中身 | 手間 |
|---|---|---|
| A（おすすめ） | **会社の Microsoft アカウント（Entra ID）でサインインする。** Azure App Service の「認証」という機能を有効にすると、アプリの手前で Microsoft のサインインを求めるようになる。アプリは、サインインした人の名前（メールアドレスなど）を、`X-MS-CLIENT-PRINCIPAL-NAME` という見出しで受け取れるので、人員の表にその列を足して結び付ける | 会社の Entra ID の管理者の協力が要る。アプリの直しは中くらい |
| B | **パスワードを足す。** 人員の表に `password` の列を足し（Django の `make_password` で、元に戻せない形にして保存）、ログインで `check_password` で比べる。初めのパスワードの配り方と、変える画面を作る | 中くらい。`migrate` が要る |
| C（すぐできる最低限） | セッションを短くする（下）。ヘルプの初期化で作る `12345` を、すぐ消す決まりにする | 小さい |

C は、A・B のどちらにするにしても先にやっておけます。セッションの長さは、勤務の長さに合わせて、使う人と決めてください（例は 12 時間。毎日ログインし直すことになります）。

**場所:** `hozen_another/settings.py` の 160〜162 行目（セッションの有効期間）

今:

```python
# セッションCookieの有効期間（秒）
#   315,360,000秒 = 3,650日（約10年）。実質的に「ログアウトするまでログイン状態を保つ」設定
SESSION_COOKIE_AGE = 315360000
```

直した後（上の行を、全部これに置き換える）:

```python
# セッションCookieの有効期間（秒）
#   60秒 × 60分 × 12時間 = 12時間。勤務が終わる頃には切れ、次の勤務でログインし直す
#   （前は 10 年＝ログアウトしない限りずっとログインしたままで、共用の PC では他人に使われやすかった）
SESSION_COOKIE_AGE = 60 * 60 * 12
```

**直ったかの確かめ方:** ログインして、開発者ツールの「Application」→「Cookies」で、`sessionid` の「Expires」が 12 時間後になっていること。

### 4.2 S-9 リポジトリの履歴に残っている Excel

🔴 すぐ ／ 📖 コードから（ファイルの見出しと行数だけ確かめた）

**どこ:** リポジトリの履歴（今のファイルには無い）

**今:**

- 氏名入りのバックアップの Excel 5 つ（リポジトリの直下・2026 年 4 月 17 日の物）は、9 月 3 日のコミット `ea674d4` で消されました。**ただし、それより前のコミットには残っています。**
- 11 月 11 日の `dffdeaf` で `media/新規 Microsoft Excel ワークシート.xlsx` が、11 月 12 日の `aee68fa` で名前を変えた `media/123.xlsx` が入り、11 月 16 日の `7b4810f` で消されました。**この 2 つのコミットにも残っています。** `aee68fa` の物は、壊れずに記録されていて、Excel として開けます。

履歴を見られる人は、だれでも、これらの Excel を取り出せます。

**直し方:**

1. **GitHub で、リポジトリを見られる人の範囲を確かめます。** リポジトリの Settings → General のいちばん下（Danger Zone）の「Change repository visibility」に、今の範囲が出ます。だれでも見られる（Public）なら、組織の管理者と相談して、Private にします。
2. 会社の決まり（個人情報・社内の情報の扱い）に従って、担当の人に知らせます。
3. 11 月 11・12 日に `media/` に入れた Excel が何のファイルで、会社の外に出てよい物かを、前任者に確かめます。出てはいけない物なら、2 の連絡に含めます。
4. **履歴からも消すか** を決めます（4 月の Excel 5 つと、3 の Excel）。消すなら、GitHub の説明「Removing sensitive data from a repository」の手順（`git filter-repo` という道具を使う）に従います。履歴を書き換えると、全員が clone し直す必要があり、GitHub Actions の実行の記録とも合わなくなります。**必ず前任者・組織の管理者と相談し、時間を決めてから** やります。
5. これからは、データ管理画面でダウンロードしたバックアップや、作業用の Excel を、**リポジトリのフォルダの中に保存しない** でください。`media/` も `.gitignore` に入れます（[D-3](#61-d-3-リポジトリに入れなくてよい物が-1257-ファイル175-mbある)）。

#### ③ お知らせ（ポップアップ）の片付け

`inquiry_views.py` に、片付ける関数 `remove_pop_up` を作ります。その問い合わせを指すお知らせを **全部** 消し、空いた枠を除いて前に詰めます。

**場所:** `kosu/views/inquiry_views.py` の 59 行目の前（inquiry_permission の後ろ）

足すコード（この行の前に入れる）:

```python
# お知らせ（ポップアップ）を片付ける。
#   人員データ（本人向け）や管理者設定（担当者向け）のお知らせ 1〜5 から、その問い合わせを指す物を全部消し、
#   文言の空いた枠も除いて前に詰める（例: [A, x, C, x, 空] → [A, C, 空, 空, 空]）。保存はしない。
#
# 引数:
#   obj       : お知らせを持つデータ（member または administrator_data）
#   inquiry_id: 問い合わせのID
# 戻り値:
#   bool: 消した物があれば True（呼んだ側が、その時だけ save() する）
def remove_pop_up(obj, inquiry_id):
  slots = [(getattr(obj, f'pop_up{i}'), getattr(obj, f'pop_up_id{i}')) for i in range(1, 6)]
  # その問い合わせを指す枠を除く（ID は文字列の項目なので、文字にそろえて比べる）
  keep = [(text, pid) for text, pid in slots if str(pid) != str(inquiry_id)]
  if len(keep) == len(slots):
    return False
  # 文言の空いた枠も除いて前に詰め、後ろの空いた枠を空にする
  keep = [(text, pid) for text, pid in keep if text not in ('', None)]
  keep += [('', '')] * (5 - len(keep))
  for i, (text, pid) in enumerate(keep, start=1):
    setattr(obj, f'pop_up{i}', text)
    setattr(obj, f'pop_up_id{i}', pid)
  return True
```

> **▶ ここで初めて出てくるコード**

#### ④ メニューの API 6 つ

メイン・人員・工数区分定義・工数・問い合わせ・管理者のメニューの API は、違いが「工数区分定義 Ver を確かめるか」「管理者設定も返すか」「だれが使えるか」の 3 つだけです。元になるクラス `LoginMemberMenu` に中身を 1 回だけ書き、6 つのクラスは、その 3 つだけを決めます（URL の対応表 `kosu/urls.py` は、クラスの名前が同じなので直さなくてよい）。

**場所:** `kosu/views/main_views.py` の 421〜463 行目（Menu の説明からクラスの終わりまで（元になるクラス LoginMemberMenu を足す））

今:

```python
# ------------------------------------------------------------
# Menu: メインMENU API
#   URL  : /api/main_menu/
#   権限 : IsLoggedIn（ログイン済みなら誰でも）
#   GET  : ログイン者の人員データと管理者設定を返す
#          （メインMENU画面で、権限・管理者に応じたメニューの表示切り替えと、
#            問い合わせ担当者向け・本人向けのお知らせ表示に使われる）
# ------------------------------------------------------------
class Menu(APIView):
  # メインMENUの表示に必要なデータを返す（GET）。
  #
  # 引数:
  #   request: HTTPリクエスト
  # 戻り値:
  #   Response: login_data（ログイン者の人員データ）と admin_data（管理者設定）
  #             工数区分定義Verが未選択の場合は 401 エラー
  def get(self, request):
    # セッションから、ログイン時に選択された工数区分定義Verを取得
    def_ver = request.session.get('input_def')

    # 工数区分定義Verが未選択の場合は 401 を返す（フロント側でログイン画面へ戻される）
    if not def_ver:
      return Response({'status': 'error', 'message': '使用する工数区分定義情報が確認できません。'}, status=status.HTTP_401_UNAUTHORIZED)

    # ログイン者の人員データ（LoginNoAuthentication がセットしたもの）
    member_data = request.user

    # 最新（IDが最大）の管理者設定を取得（無ければ初期値で作る。utils/main_utils.py の get_settings）
    admin_data = get_settings()

    # ログイン者・管理者設定をJSONに変換できる形にする
    login_serializer = MemberSerializer(member_data, many=False)
    admin_serializer = AdministratorSerializer(admin_data, many=False)

    # 送信データ
    response_data = {
      'login_data': login_serializer.data,
      'admin_data': admin_serializer.data,
    }
    return Response(response_data, status=status.HTTP_200_OK)



```

```python
# ------------------------------------------------------------
# MemberMenu: 人員MENU API
#   URL  : /api/member_menu/
#   権限 : HasAuthority（権限ありの人員のみ）
#   GET  : ログイン者の人員データを返す（人員MENU画面を開けるかの確認・表示用）
# ------------------------------------------------------------
class MemberMenu(APIView):
  # このAPIを利用できるのは「権限」ありのログイン者のみ（権限なしは 403 → 画面側でトップへ戻される）
  permission_classes = [HasAuthority]
  # ログイン者の人員データを返す（GET）。
  #
  # 引数:
  #   request: HTTPリクエスト
  # 戻り値:
  #   Response: ログイン者の人員データ（200）。工数区分定義Verが未選択の場合は 401 エラー
  def get(self, request):
    # セッションから、ログイン時に選択された工数区分定義Verを取得
    def_ver = request.session.get('input_def')

    # 工数区分定義Verが未選択の場合は 401 を返す（フロント側でログイン画面へ戻される）
    if not def_ver:
      return Response({'status': 'error', 'message': '使用する工数区分定義情報が確認できません。'}, status=status.HTTP_401_UNAUTHORIZED)

    # ログイン者の人員データ（LoginNoAuthentication がセットしたもの）
    member_data = request.user

    # ログイン者の人員データをJSONに変換できる形にして返す
    serializer = MemberSerializer(member_data, many=False)
    return Response(serializer.data, status=status.HTTP_200_OK)



```

```python
# AdministratorMenu: 管理者MENU API

    # 送信データ

      'admin_data': admin_serializer.data,
    }
    return Response(response_data, status=status.HTTP_200_OK)
```
