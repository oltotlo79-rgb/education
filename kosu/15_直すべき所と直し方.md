>
> 前の版は、11 月 11 日の `c7ea392` を読んで書きました。その後、`dffdeaf`（バグ修正）でダウンロード（S-4・B-2）が直り、まだコミットしていない変更で、ヘルプ（S-7）・ロード（B-8）・Cookie（S-5）・定義の Ver 名（B-3）など 9 項目が直りました。**前の版より前から書いてきた直し方 164 か所のうち、94 か所が、そのままの形で入っています**（前の版の時点で 50 か所、今回 44 か所）。直った所は §3 に、残っている所と新しく見つかった所（S-10）は §5 から書いています。
>
> どの項目にも、次を書いています。
>
> - **どこ:** ファイルと行番号（**手元の版** の行番号）
> - **何が困るか**と、手元で確かめた結果
> - **直し方:** 直す場所ごとに、「**今**」のコードと「**直した後**」のコードを、全部。直した後のコードは、手元の版の写しに全部入れて、アプリのテスト（349 個）と画面のテスト（534 個）が全部通ることを確かめた物です（§10）
> - **直ったことの確かめ方**

> ⚠️ **いちばん急ぐこと:** 手元の版の直しの多くは、**まだコミットも push もしていません**（§3.1 の表で「手元だけ」と書いた物）。GitHub の `master`（`dffdeaf`）は、**アプリのテストが 353 個のうち 5 個落ちる** 状態のままです。手元の版で落ちるのは、[B-10](#610-b-10-ログイン以外の理由でも-401-を返し画面がログイン画面へ飛ぶ) の 2 個だけです（[T-5](#85-t-5-アプリのテストが落ちるテストだけ先に入った)）。**[B-10](#610-b-10-ログイン以外の理由でも-401-を返し画面がログイン画面へ飛ぶ) と [S-10](#510-s-10-ヘルプの回数の上限が頼みの見出しの書き方しだいで効かない)（ヘルプの回数の上限の見分け方）を直し、テストが全部通ることを確かめてから、手元の変更と一緒にコミットして push してください**（手元で確かめた。全部入れると 349 個全部 OK）。GitHub Actions（`master` に入れると本番に出す仕組み）は、今も GitHub の画面で手動で止めてあります（2026 年 11 月 12 日に確かめた）。**[T-5](#85-t-5-アプリのテストが落ちるテストだけ先に入った) と [D-1](#71-d-1-github-actions-がテストを流さずに本番へ出す作りのまま)（Actions でテストを流す）を直すまでは、Actions を動かさないでください。**

## 1. この巻の読み方

### 1.1 印の意味

**急ぐ度**

| 印 | 意味 |
|---|---|
| 🔴 すぐ | 本番のデータが守られていない、または使えなくなる。ほかの作業より先に直す |
| 🟠 早めに | 動かない、または壊れやすい。使う人が困る |
| 🟡 余裕のある時に | 整理・改善。直さなくても、すぐには困らない |

**今の状態**（前の版＝`c7ea392` の時の一覧と比べて）

| 書き方 | 意味 |
|---|---|
| 新しく見つかった | 前の版には無かった |
| 前から残っている | 前の版から、まだ直っていない |
| 一部だけ直った | 前の版の直し方の一部が入った。残りを書いている |
| 直った（手元だけ） | 前任者の PC の作業フォルダでは直っているが、**まだコミット・push していない**。GitHub の `master` には入っていない。§3.1 に、どう直ったかと、確かめた結果を書いた |
| 直った | GitHub の `master` に入っている。§3 に、どう直ったかと、確かめた結果を書いた |

**どうやって分かったか**

| 印 | 意味 |
|---|---|
| ✅ 手元で再現 | 手元の版を別のフォルダに写し、メモリの中だけのデータベースで動かして、本当にそうなることを確かめた（本番には一切触っていない。§10） |
| 📖 コードから | コードを読んで分かった。動かしては確かめていない |

**番号の頭の文字:** S ＝ 安全（Security）、B ＝ 不具合（Bug）、D ＝ 開発・運用の整理（Development）、T ＝ テスト（Test）。番号は前の版と同じ物を使っています（直った番号も、欠番にしないで残しています）。新しい番号は [S-10](#510-s-10-ヘルプの回数の上限が頼みの見出しの書き方しだいで効かない) の 1 つです。

### 1.2 「今」と「直した後」の読み方

直し方は、次の形で書いています。

- **場所:** ファイルと、手元の版での行番号。たとえば「`kosu/tasks.py` の 328 行目」。
- **今:** その行の、今のコード（コメントも含めて、ファイルのとおり）。
- **直した後:** 「今」の行を、全部これに置き換えます。
- 「この行の前に入れる」と書いてある物は、何も消さずに、その行の前に足します。
- 「新しいファイル」と書いてある物は、そのファイルを新しく作り、中身を全部入れます。

> ⚠️ **行番号は、上から直していくと、ずれます。** 1 つのファイルの中で何か所も直す時は、**下の方の場所から** 直すか、行番号ではなく「今」のコードを、エディターの検索（`Ctrl` ＋ `F`）で探して置き換えてください。

> 📌 **手元の版と GitHub の `master` で、行番号が違うファイルがあります。** 手元で変えた・消した 20 ファイル（§3.1）は、コミットするまで、GitHub の物と行番号が違います。それ以外のファイル（`kosu_views.py`・`models.py`・`urls.py` など）は、GitHub の `master`（`dffdeaf`）と同じです。

> ⚠️ **本番のホスト名（住所）は、この資料には書いていません。** コードの中で `<本番のホスト名>` と書いた所は、今のファイルに書いてある名前を、そのまま使ってください。

### 1.3 この巻で使う言葉

| 言葉 | 意味 |
|---|---|
| API（エーピーアイ） | 画面（React）がサーバー（Django）に「データをちょうだい」「これを保存して」と頼む窓口。`/api/member_new/` のような URL の 1 つ 1 つ（07 巻） |
| ログインの確かめ（認証） | 「今、だれがログインしているか」を確かめること。このアプリでは、ログインすると **セッション**（サーバーが覚えておく、その人用のメモ）に従業員番号（`login_No`）が入り、`kosu/permissions.py` の `LoginNoAuthentication` がそれを読む |
| 権限の確かめ（認可） | 「その人に、その操作をしてよいか」を確かめること。人員の表の「権限（`authority`）」と「管理者（`administrator`）」の 2 つのスイッチを、`permissions.py` の `HasAuthority`・`IsAdministrator` が確かめる |
| CSRF（シーサーフ） | ログインしたままの人が、別の（悪い）サイトを開いた時に、そのサイトが裏でこのアプリへ「消して」などを送らせる攻撃。防ぐには、このアプリの画面だけが知っている合言葉（**CSRF トークン**）を、書き込みの時に一緒に送らせて確かめる |
| CORS（コルス） | 別のサイトの JavaScript が、このアプリの API の返事を読んでよいかを、サーバーが答える仕組み |
| Cookie（クッキー） | ブラウザがサイトごとに覚えておく小さなデータ。ログインのセッションの番号（`sessionid`）も、CSRF トークン（`csrftoken`）もここに入る |
| ステータスコード | API の返事に付く 3 けたの番号。200 ＝ 成功、400 ＝ 送った物がおかしい、401 ＝ ログインしていない、403 ＝ してはいけない、404 ＝ 見つからない、409 ＝ ほかのデータとぶつかる、429 ＝ 呼びすぎ、500 ＝ サーバーの中でエラー（09 巻） |
| トランザクション | 何件もの書き込みを「全部する」か「全部しない」かにまとめる仕組み。途中で失敗したら、それまでの書き込みも取り消す（08 巻） |
| マイグレーション | データベースの表の形の変更を書いたファイル（`kosu/migrations/`）。`migrate` で本物のデータベースに当てる（08 巻） |
| 手元の版 | この巻で読んだコード。前任者の PC の作業フォルダの中身（GitHub の `master` の `dffdeaf` ＋ まだコミットしていない変更。2026 年 11 月 11 日の夜の時点） |

### 5.10 S-10 ヘルプの回数の上限が、頼みの見出しの書き方しだいで効かない

🟠 早めに ／ 新しく見つかった（前の版の [S-7](#57-s-7-ヘルプ画面の初期化-api総当たり途中の失敗パスワード未設定直った手元だけ) の直し方に足りなかった所） ／ ✅ 手元で再現

**どこ:** `kosu/views/main_views.py` 262 行目（`Help`）・379 行目（`HelpPass`）の `throttle_classes = [ScopedRateThrottle]`

**今:** 回数の上限の部品（DRF の `ScopedRateThrottle`）は、「同じ所からの頼みか」を、頼みに付いてくる見出し `X-Forwarded-For`（中継のサーバーが、本当の送り元の住所を書いて渡す見出し）で見分けます。DRF の初めの設定（`NUM_PROXIES` を書いていない時）では、**見出しの中身を全部つなげた文字** で見分けます（手元に入っている DRF 3.14.0 の `throttling.py` 23〜40 行目で確かめた）。ところが、この見出しの中身は、いつも同じとは限りません。

- 中継は、ふつう、本当の送り元の住所を見出しの **いちばん後ろ** に足して渡します。その前の部分は、送る側が自由に書けます。
- 住所の後ろに、つなぐたびに変わるポート番号（`:51234` など）が付く中継もあります。

どちらでも、見出しの中身が変わるたびに、別の所からの頼みとして数え直されます（本番の App Service の見出しの形は、この巻では確かめていません）。

✅ **手元で試した結果（手元の版）:** 上限を 1 時間に 5 回にして、見出しの前の部分が毎回違う頼みを、同じ送り元から 6 回送ると、6 回とも 403 で、429 になりませんでした（下の③のテストが、手元の版では「[403, 403, 403, 403, 403, 403] != [403, 403, 403, 403, 403, 429]」で落ちる）。

**何が困るか:** ヘルプの API は、ログインしなくても呼べます。上限が効かないと、[S-7](#57-s-7-ヘルプ画面の初期化-api総当たり途中の失敗パスワード未設定直った手元だけ) で防いだはずの、パスワードの総当たりができてしまいます。

**直し方:** 「同じ所か」を、見出しの **いちばん後ろ**（App Service の中継が足した、本当の送り元）の住所だけで見分ける部品 `HelpRateThrottle` を作り、`Help`・`HelpPass` で使います。住所にポート番号（`:51234` など。つなぐたびに変わる）が付いていたら外します。

① `Help` の説明の前に、部品を足します。

**場所:** `kosu/views/main_views.py` の 248 行目の前（Help の説明の前）

足すコード（この行の前に入れる）:

```python
# ------------------------------------------------------------
# HelpRateThrottle: ヘルプの呼び出し回数の上限（Help・HelpPass で使う）
#   ScopedRateThrottle（DRF の部品）は、初めの設定では、頼みに付いてくる見出し X-Forwarded-For の
#   中身を全部つなげた文字で「同じ所か」を見分ける。見出しの前の部分は送る側が自由に書けるので、
#   書き方が変わるたびに「別の所」として数え直しになり、上限が効かない。
#   そこで、App Service の手前の中継が最後に足した、本当の送り元の住所（IP アドレス）だけで見分ける。
# ------------------------------------------------------------
class HelpRateThrottle(ScopedRateThrottle):
  # 「同じ所か」を見分ける文字（送り元の IP アドレス）を返す。
  #
  # 引数:
  #   request: HTTPリクエスト
  # 戻り値:
  #   str: 送り元の IP アドレス（ポート番号は付けない）
  def get_ident(self, request):
    xff = request.META.get('HTTP_X_FORWARDED_FOR')
    # 中継が無い時（手元で runserver を使う時など）は、つないできた相手の住所
    if not xff:
      return request.META.get('REMOTE_ADDR')
    # いちばん後ろが、App Service の中継が足した、本当の送り元
    addr = xff.split(',')[-1].strip()
    # "[2001:db8::1]:51234"（IPv6 とポート番号）の形なら、[ ] の中だけにする
    if addr.startswith('['):
      return addr[1:addr.find(']')] if ']' in addr else addr
    # "203.0.113.7:51234"（IPv4 とポート番号）の形なら、ポート番号を外す
    #   （ポート番号はつなぐたびに変わるので、付けたままだと毎回「別の所」になる）
    if addr.count(':') == 1:
      return addr.split(':')[0]
    return addr



```

<!-- first-use -->

> **▶ ここで初めて出てくるコード**
>
> - **`.startswith()`**（Python）: 文字列が、その中身で始まっていれば `True` を返すメソッド。`login_member.shop.startswith('組長以上')` は、ショップが「組長以上(P,R,T,その他)」「組長以上(W,A)」のどちらかなら `True` です。
> - **`.find()`**（Python）: 文字列の中で、渡した文字が最初に出てくる位置（0 から数えた番号）を返すメソッド。見つからない時は `-1` を返します。`addr[1:addr.find(']')]` は、`[2001:db8::1]:51234` のような文字から、`[` の次から `]` の手前まで（`2001:db8::1`）を取り出します。
> - **`[-1]`**（Python）: `items[-1]` は、最後の 1 つです。`[-2]` は後ろから 2 つ目です。
> - **`ScopedRateThrottle`**（Django REST framework）: 同じ所（IP アドレス）からの呼び出しの回数を数えて、上限を超えたら 429（呼びすぎ）を返す部品。ビューに `throttle_classes = [ScopedRateThrottle]` と `throttle_scope = 'help'` を書くと、`settings.py` の `REST_FRAMEWORK` の `DEFAULT_THROTTLE_RATES` の `'help': '5/hour'`（1 時間に 5 回）が上限になります。
> - **`.META`**（Django）: Django の `request.META` は、要求の見出しやサーバーの情報が入った辞書です。`request.META.get("REMOTE_ADDR")` で、送ってきた所のアドレスが分かります。

### 7.6 D-6 HTTPS まわりの設定が足りない

🟡 余裕のある時に ／ 前から残っている ／ 📖 コードから

**今:** Azure App Service は、HTTPS で受けた頼みを、中のアプリへは HTTP で渡します。アプリは「HTTPS で来た」と分からないので、`request.is_secure()` が `False` になります。今は `CSRF_TRUSTED_ORIGINS` に本番の `https://…` を書いてあるので CSRF の確かめは通りますが、HTTPS を前提にした Django の守り（Referer の確かめなど）が働きません。

**直し方:** `CSRF_TRUSTED_ORIGINS` のすぐ後ろに足します。

**場所:** `hozen_another/settings.py` の 318 行目の前（CSRF_TRUSTED_ORIGINS のすぐ後ろ）

足すコード（この行の前に入れる）:

```python

# Azure App Service は、HTTPS で受けたリクエストを、中のアプリへは HTTP で渡す。
# その時に付く X-Forwarded-Proto ヘッダーを見て「本当は HTTPS だった」と分かるようにする
#   （request.is_secure() が正しくなり、CSRF の確かめも HTTPS として行われる）
SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')
# CSRF トークンの Cookie も、本番（DEBUG=False）では HTTPS の時だけ送る
CSRF_COOKIE_SECURE = not DEBUG
```

HTTPS だけで使うと決めたら、ブラウザに「この住所は HTTPS だけで開く」と覚えさせる `SECURE_HSTS_SECONDS` も足せます。大きくすると、その間 http で開けなくなるので、小さい値（例: `3600` ＝ 1 時間）から始めます。

## 11. この巻のまとめ

- 前の版でいちばん急ぐと書いた、**テストだけが先に入って落ちていた 9 個（[T-5](#85-t-5-アプリのテストが落ちるテストだけ先に入った)）は、2 個まで減りました。** ダウンロード（[S-4](#54-s-4-ダウンロードの-api-が渡された場所のファイルをそのまま返して消そうとする直った)・[B-2](#62-b-2-バックアップのダウンロードでexcel-ではなく画面の-html-が落ちてくる直った)）は GitHub の `master`（`dffdeaf`）に入り、ヘルプ（[S-7](#57-s-7-ヘルプ画面の初期化-api総当たり途中の失敗パスワード未設定直った手元だけ)）・ロード（[B-8](#68-b-8-データのロードが途中で失敗するとデータが半分だけ消える直った手元だけ)）・Cookie（[S-5](#55-s-5-セッションの-cookie-が別のサイトからの頼みにも付く直った手元だけ)）・定義の Ver 名（[B-3](#63-b-3-定義の-ver-名を変える消すとその-ver-で入れた工数が開けなくなる直った手元だけ)）など 9 項目は、手元の版で、前の版の直し方のとおりに直っています。
